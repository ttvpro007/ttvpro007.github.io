Portfolio Site Builder

A local-first, git-backed site builder for one portfolio: edit in a GUI or let an agent edit through the CLI, then Test, Stage and Go live. Agents are first-class users, but every file stays readable by a person and the editor stays learnable without docs.

It is also the working prototype that Loom, the engine behind the Atelier studio, is extracted from. After milestone MX this repo becomes a plain site repo: it consumes @loom/* and @loom/kit-portfolio and never edits engine or kit code again.

Content format: docs/content.md. Release flow: docs/release.md. How the code fits together: the architecture map (docs/architecture.html). Task-level work: git history and the Claude sessions named on each milestone.
Where work lands
Until MX, everything is built here. From MX on, engine work (formats, blocks, builder, CLI, release gate) lands in the private loom repo and portfolio-specific blocks in loom-kit-portfolio, both under GitHub/Business. This repo then only bumps package versions and edits content/. Each milestone after M4 says which side its work lands on. The Loom contracts in Business/loom/docs/contracts/ are the source of truth for formats.

The "Evidence" line on each milestone is what the repo showed when this revision was written. It is not a tick. The ticks are yours, so a box stays empty until you check it.

Milestone plan

Useful from M1. Projects can be added and shipped without touching code today. M4 is where it becomes a site builder: the first milestone where the site's structure changes without a code edit. Then MX splits the prototype into Loom, the portfolio kit and this site, and must leave the live site pixel-identical. Everything after MX adds freedom, is built in Loom, and is optional, not owed.

Sizes are rough: S is one agent session, M is two or three, L is several plus your review. None of them has been measured.

Scope

Not building
  • Absolute (x/y) positioning of elements.
  • Accounts, logins or more than one editor at a time. Git is the history.
  • A hosted service, or other people's sites, in this repo. That is Atelier and Loom, in their own repos under GitHub/Business.
  • A database. Content stays as JSON and Markdown files.
  • Live fields and an /editor for this site. The portfolio stays a static build; Loom's live fields are for client sites.
  • Engine or kit code in this repo after MX. Changes go to loom or loom-kit-portfolio and arrive as a version bump.
Deferred with intent
  • After M7, if you edit away from your desk: host the admin privately to edit from a phone.
  • After M6: per-breakpoint overrides beyond show/hide.
  • Whenever it's fun: "describe a section" generation by an agent through the CLI.

Standing assumptions

One owner and one site. Agents do most of the building, in separate sessions, and you review and merge. The site stays a static Vite and React build on GitHub Pages. After MX its build pulls private packages from GitHub Packages, published as @ttvpro007/loom-* and aliased to @loom/*. Tools like Wix, Webflow and Framer already do visual editing better than this ever will. The reasons to build anyway: content stays in your repo, every change is a reviewable commit, and agents can edit the site through the same CLI and checks as you.
